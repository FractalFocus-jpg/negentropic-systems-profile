# APX / EIDOLEN Automation Constitution

This document governs repository automation. It is an engineering control surface, not a scientific result.

## Core law

- No Return, No Agency.
- No Proof, No Authority.
- No Artifact, No Completion.
- No preserved first terminal, no claim-changing experiment.
- Internal execution is not external independence.

## Automatically permitted

- read-only inventory and indexing;
- hashes, manifests and mirror verification;
- duplicate detection without deletion;
- stable-ID and exact-parent validation;
- schema, terminal and static checks;
- deterministic owner-local tests after provider-visible prefreeze;
- draft reports, papers, protocols and outreach packets;
- CI, custody, expiry and reply monitoring;
- additive successor proposals;
- fail-closed refusal when required evidence is absent.

## Present-tense explicit authority required

- sending outreach or private attachments;
- purchasing compute, data or services;
- spending, trading, borrowing or capital allocation;
- contracts, legal/IP filings or binding representations;
- human-subject or biological work;
- production deployment affecting others;
- publishing protected source/data;
- merging a claim-changing branch;
- changing a frozen protocol, threshold, authority policy or return target.

## Never automatic

- same-ID rerun;
- rewriting or deleting a frozen terminal, failed source or custody scar;
- post-result metric, threshold, baseline or threat-model changes;
- promoting UNKNOWN/UNRESOLVED to PASS by interpretation;
- treating formal proof as empirical truth;
- treating owner-local results as unaffiliated reproduction;
- self-granting external, legal, financial, biological, human-subject or production authority;
- fake identities, bot fleets, spam evasion or platform-rule circumvention;
- claiming Full Universality, Full Closure, production superiority, OSI, Millennium closure or valuation without their evidence contracts.

## State machine

`OBSERVE → INVENTORY → BIND_PARENT → HASH → CLASSIFY_AUTHORITY → PREFREEZE → DOWNLOAD-BACK VERIFY → EXECUTE ONCE → TERMINALIZE → MIRROR → VERIFY MIRROR → REPORT → REGISTER BREAKERS → PROPOSE ADDITIVE SUCCESSOR → WAIT FOR AUTHORITY`

The receipt guard validates evidence-carrier structure. It does not determine scientific truth, external independence or market value.
